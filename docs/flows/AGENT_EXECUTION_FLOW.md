## 1. Sequential vs. Hierarchical Execution Lifecycles

The builder supports two primary execution patterns configured via the Crew Config node:

### 1.1 Sequential Process (`Process.sequential`)
Tasks execute one after another in a linear pipeline. The output of prior tasks can automatically serve as context for subsequent tasks.

```mermaid
graph LR
    Task1["Task 1: Market Intelligence<br/>(Assigned: Lead Researcher)"] -->|"Output: raw_research_data.md"| Task2["Task 2: Executive Synthesis<br/>(Assigned: Brief Writer)"]
    Task2 -->|"Output: executive_brief.md"| Complete([Crew Kickoff Finished])
```

### 1.2 Hierarchical Process (`Process.hierarchical`)
A Manager LLM (e.g. `gpt-4o`) evaluates incoming tasks, delegates them dynamically across agents, validates the quality of intermediate outputs, and synthesizes the final result.

```mermaid
graph TD
    Manager["Manager LLM (e.g. GPT-4o)"]
    Manager -->|"Delegates Task A"| Agent1["Principal Architect"]
    Manager -->|"Delegates Task B"| Agent2["Security Auditor"]
    Agent1 -->|"Returns Architecture Audit"| Manager
    Agent2 -->|"Returns Vulnerability Matrix"| Manager
    Manager -->|"Validates Quality & Synthesizes"| FinalResult([Final Crew Report])
```

## 2. Agent Tool Invocation Loop

Each agent operates within a structured tool-use loop:

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> TaskAssigned: Task Dispatched
    TaskAssigned --> Thinking: Reasoning over Backstory & Goal
    Thinking --> ToolSelection: Requires External Information?
    ToolSelection --> ToolExecution: Call SerperDevTool / ScrapeWebsiteTool / etc.
    ToolExecution --> Thinking: Observe Tool Output
    Thinking --> Completed: Output Matches Expected Criteria
    Completed --> [*]
```
